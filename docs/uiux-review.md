# UI/UXレビュー

## 修正結果

以下の25件に対応する実装を追加した。画面と機能の修正内容は次のとおり。

| 対象 | 修正した動作 |
| --- | --- |
| お気に入り | 事例IDと利用者IDで保存・削除し、一覧と詳細で状態を共有。失敗時の案内とログインへの復帰先を追加 |
| 削除 | 管理者の事例削除に、対象名と取り消せない旨を示す確認を追加 |
| 金額 | 入力・検索に円単位を明示。費用は通貨形式で表示し、下限と上限の逆転を検出 |
| 施工写真 | 配列順で施工前後を断定する表示を廃止。「施工写真」として登録順に表示し、拡大・前後移動・キーボードでの終了に対応 |
| 問い合わせ | 企業宛ての相談に案内と選択肢を統一。送信先を表示し、会員登録・ログイン・再設定への案内を別に配置 |
| フォーム | 項目別のエラー、最初のエラーへのフォーカス、保存中表示、連打防止、未保存の変更の保護を追加 |
| 検索 | 条件の表示・解除、詳細から条件とページを保持して戻る操作、スマートフォンで条件を開閉する操作を追加 |
| 一覧 | ページ番号を省略。企業検索0件・未登録・お気に入り0件を区別し、次の操作を案内 |
| 認証 | パスワード再設定の申請・更新画面を追加。認証エラーを利用者向けの案内に変更 |
| アクセシビリティ | メニューのフォーカス管理・Escape終了・背景操作の抑止、検索欄のフォーカス表示、本文へのリンク、主領域の重複解消、文字サイズ拡大、動きを減らす設定、ページタイトルを追加 |

金額の既存保存値は変換していない。写真の役割を保存するDB変更も行わず、未確認の写真に施工前後の見出しを付けない方法で修正した。

パスワード再設定メールを使う環境では、SupabaseのRedirect URLsに `/reset-password` を登録する必要がある。[セットアップ手順](./supabase-setup.md)に追記した。実DBへの保存・削除とメール配送は、接続情報のないローカル環境では未確認。

検証は `npm run lint`、`npm run typecheck`、`npm run test`（15ファイル・43件）、`npm run build`、`npm run test:e2e -- --workers=2`（30件）がすべて成功した。お気に入りの保存失敗、削除のキャンセル、未保存の変更の保護、検索条件付きの戻り先、パスワード再設定の入力検証は、DBやメール送信をモックして確認した。公開画面の表示、モバイルメニュー、検索条件の開閉、本文への移動、フォーカス表示はChromiumで確認した。

## 初回レビューの記録

以下は修正前の調査結果。ソースの行番号とブラウザーの測定値も修正前を示す。

このアプリの修正順を決めるため、公開画面と会員・企業・管理者向けの実装を調べた。
先に直したいのは、保存したつもりになるお気に入り、確認なしの事例削除、費用の単位、施工前後の写真の扱い、問い合わせ先の案内である。

修正候補は25件（P1：6件、P2：18件、P3：1件）。

以下の優先度は、実装から確認できる利用者への影響に基づく提案。P1は誤操作・情報の誤認・主要機能の不成立、P2は操作や理解の妨げ、P3は補助的な改善を表す。利用者調査やアクセス解析による順位ではない。

## app/components/molecules/index.tsx

- `app/components/molecules/index.tsx:50` — **P1：お気に入りが保存されない。** 事例IDを受け取らず、クリック時にローカルの真偽値だけを切り替える。再表示すると解除され、DBから取得するお気に入り一覧とも一致しない。事例IDと保存済み状態を渡し、追加・削除を保存する。未ログイン時の案内と保存失敗時の通知も必要。
  - 確認条件：追加後に詳細・一覧・マイページを移動し、再読み込みしても同じ状態が表示される。
- `app/components/molecules/index.tsx:131` — **P2：全ページ番号を並べる。** 総ページ数に比例してリンクが増える。前後のページと先頭・末尾だけを表示し、間を省略する。件数が多い場合もスマートフォンの画面幅に収める。

## app/routes/admin-dashboard.tsx

- `app/routes/admin-dashboard.tsx:162` — **P1：削除ボタンの押下で事例を即時削除する。** 確認も取り消しもない。企業ダッシュボードには確認があるが、管理者画面にはない。事例名と削除の影響を示す確認を追加し、削除操作には危険操作用の表示を使う。
  - 確認条件：確認のキャンセルでは削除リクエストが送られず、確定時だけ対象を削除する。

## app/components/organisms/index.tsx

- `app/components/organisms/index.tsx:160` — **P1：予算に金額の単位がない。** 下限・上限だけでは円と万円を判断できない。保存する単位を確認して入力欄に明示し、事例登録・編集・費用表示でも統一する。関連：`app/routes/company-case-new.tsx:146`、`app/routes/company-case-edit.tsx:247`、`app/features/cases/public-data.client.ts:51`。表示には `Intl.NumberFormat` を使い、未入力は「要相談」など意味の分かる表記にする。
- `app/components/organisms/index.tsx:50` — **P2：モバイルメニューのフォーカス制御がない。** 開くと背景スクロールを止めるが、メニューへのフォーカス移動、背景の操作抑止、Escapeでの終了がない。閉じた際は開くボタンへ戻す。キーボードで背景フォームへ移動できないようにする。
- `app/components/organisms/index.tsx:150` — **P2：検索条件をまとめて解除できない。** 条件を入力し直す必要がある。「条件をクリア」と現在の条件の表示を追加し、結果がない場合にも解除を案内する。

## app/routes/case-detail.tsx

- `app/routes/case-detail.tsx:26` — **P1：写真の配列順を施工前後として扱う。** 2枚目をBEFORE、1枚目をAFTERと固定している。一方、登録・編集画面に施工前後を指定する操作がないため、利用者が写真を逆に解釈する可能性がある。写真に施工前・施工後・その他の役割を保存し、画面でも指定できるようにする。役割が不明な写真には施工前後と断定する見出しを付けない。
- `app/routes/case-detail.tsx:31` — **P2：「検索結果へ戻る」で検索条件が消える。** 戻り先が常に `/search` で、地域・予算・ページを引き継がない。一覧からの遷移時に検索URLを保持する。直接開いた詳細からは検索一覧へ戻れるようにする。
  - 確認条件：条件付き検索の2ページ目から詳細を開き、画面内の戻るリンクで同じ条件・ページへ戻る。
- `app/routes/case-detail.tsx:41` — **P2：追加写真を拡大できない。** 写真は画像要素だけで、CSSでは120×82pxに切り抜く。リンクかボタンから元画像を確認できるようにする。拡大表示にはキーボードで開閉できる操作を用意する。
- `app/routes/case-detail.tsx:43` — **P2：`main` が入れ子になっている。** `PublicLayout` の `main` 内に別の `main` がある。内側は `section` または `div` にして、ページの主領域を一つにする。

## app/routes/contact.tsx

- `app/routes/contact.tsx:102` — **P1：案内する相談内容と送信先が合っていない。** 会員登録の相談も受け付ける文言だが、送信には施工企業の選択が必須で、全種別をその企業へ送る。運営向けと企業向けを分け、送信前に宛先が分かるようにする。運営向けの受付を作らない場合は、現在受け付けられる内容に案内を合わせる。
- `app/routes/contact.tsx:112` — **P2：入力エラーがフォーム上部の総合メッセージだけ。** どの欄を直すか特定できず、エラー項目へのフォーカス移動もない。項目ごとに理由を表示し、`aria-invalid` と `aria-describedby` で関連付ける。送信時は最初のエラーへ移動する。企業・事例の登録編集画面にも同じ対応が必要。

## app/routes/company-case-new.tsx / company-case-edit.tsx / company-profile-edit.tsx

- `app/routes/company-case-new.tsx:154` — **P2：登録・更新中の表示と連打防止がない。** 新規登録、事例編集（254行）、企業編集（191行）の送信ボタンは処理中も同じ表示で押せる。送信開始後は無効化し、「保存中…」などの状態を通知する。特に画像アップロード中は完了したか分かる表示が必要。
- `app/routes/company-case-edit.tsx:229` — **P2：未保存の入力を失う。** 事例追加・編集と企業編集に、変更後の画面移動を確認する処理がない。変更を検知して画面遷移・タブを閉じる操作を保護し、保存成功後は確認を解除する。写真の追加・削除も変更として扱う。

## app/routes/company-profile-edit.tsx / company-apply.tsx

- `app/routes/company-profile-edit.tsx:184` — **P2：入力内容に合う型・自動入力指定が不足。** 電話番号は `type="tel"` と `autoComplete="tel"`、Webサイトは `type="url"`、所在地は用途に合う `autoComplete` を指定する。企業申請の電話番号（`app/routes/company-apply.tsx:71`）も対象。

## app/features/auth/auth-panel.tsx / auth.client.ts

- `app/features/auth/auth-panel.tsx:32` — **P2：パスワードを忘れた場合の復旧導線がない。** リセット申請、メール送信後の案内、再設定画面を用意する。登録時には8文字以上という条件を入力前に示す。
- `app/features/auth/auth.client.ts:12` — **P2：利用者向け認証エラーに環境設定の確認を求めている。** Supabaseや `.env` の確認は一般利用者にはできない。認証情報の誤り、メール確認待ち、通信障害に応じて次の行動を案内し、開発者向けの設定情報は画面に出さない。

## app/routes/companies.tsx / favorites.tsx / mypage.tsx

- `app/routes/companies.tsx:61` — **P2：検索の0件と登録企業自体の0件を区別していない。** 検索語に一致しない場合も「登録されている企業がありません」と表示する。「条件に合う企業がありません」と条件解除リンクを用意する。
- `app/routes/favorites.tsx:40` — **P2：お気に入りが0件のとき説明も次の操作もない。** 「まだ登録していません」と施工事例を探すリンクを表示する。マイページの新着・お気に入りセクション（`app/routes/mypage.tsx:36`、41行）も空配列への対応が必要。

## app/routes/search.tsx / app/app.css

- `app/routes/search.tsx:62` — **P2：スマートフォンで結果の前に全検索項目が並ぶ。** 820px以下では1列に変わるが、フォームは常時展開される。結果件数と検索結果を先に確認できる配置にし、検索条件は開閉できるようにする。適用中の条件数を開閉ボタンに示す。
- `app/app.css:221` — **P1：検索欄のフォーカス表示を消している。** `.search-bar input` の `outline: 0` に代替表示がない。入力欄に `:focus-visible`、検索バー全体に `:focus-within` の表示を加える。
- `app/app.css:261` — **P2：フォームの文字が12px、カード補足が9px。** 小さい画面でも同じ指定になる。フォームは16pxを基準に見直し、カード本文や補足も拡大する。iOSで入力時に拡大されないかは実機で確認する。文字サイズの拡大後もラベルと操作を切らさない。
- `app/app.css:1497` — **P3：メニューの動きを減らす設定に対応していない。** `prefers-reduced-motion: reduce` ではメニューの移動アニメーションを無効にする。

## app/root.tsx

- `app/root.tsx:34` — **P2：画面によってページタイトルが空になる。** ルートの共通タイトルがなく、企業一覧・問い合わせ・ログイン・新規登録にも個別のタイトルがない。共通のフォールバックと各画面のタイトルを設定する。詳細画面は事例名・企業名を含め、複数タブや履歴で区別できるようにする。
- `app/root.tsx:49` — **P2：共通ナビゲーションを飛ばすリンクがない。** キーボード操作で本文に直接移動できるスキップリンクを追加する。各レイアウトの `main` に遷移先IDを設け、フォーカス時にリンクを表示する。

## 修正順の提案

1. お気に入りの保存、管理者の削除確認、金額の単位、写真の役割、問い合わせ先を直す。利用者の操作結果や判断に関わるため、先に確認する。
2. 共通のフォーカス表示・フォームのエラー表示・保存中の表示を直し、検索条件の保持とモバイルの結果表示を整える。
3. 空表示、認証の復旧導線、写真の拡大、文字サイズ、動きを減らす設定を整える。

## 方法と確認範囲

- 使用スキル：[vercel-labs/agent-skills / web-design-guidelines](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md)。レビュー時に指定先の[Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)を取得して確認した。英文の表記規則は日本語UIへ機械的に適用していない。
- 対象：`app/routes`、共通コンポーネント、認証、公開データ取得、画像表示、共通CSS、既存E2Eの内容。ソースコードに基づく指摘と、画面操作で確認した結果を区別する。
- ブラウザー確認：ローカル開発サーバーの公開6画面（ホーム、検索、企業一覧、問い合わせ、ログイン、新規登録）をChromiumで表示した。画面幅は1280・390・320px、高さは844px。スクリーンショットは1280・390pxで取得した。以下の表以外の指摘はソースコードに基づく。
- 会員・企業・管理者向けの保存、削除、メール送信は実行していない。認証後の画面、実データでの表示、iOS実機、スクリーンリーダーの読み上げは未確認。
- アプリのコードは変更していない。この文書は修正候補と確認条件をまとめたもの。

| 画面操作で確かめた項目 | 結果 |
| --- | --- |
| モバイルメニューのEscape操作 | 閉じない |
| モバイルメニューを開いた後のTab操作 | 背景のキーワード・地域・予算などへ移動する |
| 企業検索欄のフォーカス表示 | 入力欄・検索バーに有効なアウトラインや影がない |
| 動きを減らす設定時のメニュー | 220msのトランジションが残る |
| モバイル幅の検索結果の位置 | 検索結果セクションの上端が719.5px。結果の内容を見るにはスクロールが必要 |

問い合わせ先企業と施工事例が0件のローカル環境で確認した。企業検索の「登録なし」表示は画面で確認したが、企業が存在し、検索語だけが一致しない条件はソースコードで確認した。お気に入りの保存や検索条件付き詳細からの復帰は、認証・実データを用いる確認が残る。
